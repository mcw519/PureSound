    Model details
    
      
    
        

    
      
    About Playground
    
      
    
        
    The recording is prepared as mono 16 kHz, streamed through the model 20 ms at a time as it would be on a device, and aligned back to the input so the two play in step.
    
        
    Input
    
        
      
          
    • File: drop or pick a recording, or try one of the samples.
      • 
          
    • Record: records at 16 kHz with the browser's echo cancellation, noise suppression and gain control off, so the model hears your capture chain as it is.
      • 
          
    • Live: streams the microphone through the model and the settings, 20 ms at a time. Listen to changes only what you hear; when you stop, the session opens as a comparison.
      • 
        
    
        
    Listening
    
        
    The player puts the input and every output on one transport. Space plays or pauses, 1–9 switch tracks while it plays, drag to select a region, L loops it and Z zooms to it. Removed is the input minus the output: what the model took out.
    
        
    Settings
    
        
      
          
    • Runs on: the server, or this device, where the model runs in this browser and the audio is not uploaded. A device run takes a model with a device build, cannot chain Run first, has no DNSMOS and is not kept in History.
      • 
          
    • Run first chains another enhancement model ahead of this one, for example noise suppression before voice isolation.
      • 
          
    • Dry blend mixes the untouched input back in; 1.00 is the model alone.
      • 
          
    • Onset guard leaves the input untouched until a talker has been heard for a second: fewer deleted words, less suppression at the start.
      • 
        
    
        
    Ctrl+Enter runs.
    
      
    
        
    
      
    About Verify
    
      
    
        
    The speaker model turns each recording into a 192-dimensional embedding and compares the two with cosine similarity. The pair matches when the similarity is above the threshold.
    
        
      
          
    • Reference voice: one clear speech sample of the speaker.
      • 
          
    • Test voice: the recording to check, the same speaker or an impostor.
      • 
          
    • A higher threshold rejects more impostors, and more true speakers too.
      • 
        
    
        
    Ctrl+Enter verifies.
    
      
    
        
    
      
    About Compare
    
      
    
        
    Every selected model runs on the same recordings, next to the unprocessed input's own scores. One clip shows what happens; five or more give a paired interval that can tell a real difference from noise.
    
        
    Steps
    
        
      
          
    1. Choose recordings: one or more noisy clips, or the samples. A clean reference with the same file name adds SI-SDR, STOI and PESQ.
      2. 
          
    2. Choose models: each row is a model and its settings; + adds another setting of the same model, for example two dry blends.
      3. 
          
    3. Read and listen: scores sit against the unprocessed row, and every output plays on one transport.
      4. 
        
    
        
    Reading the table
    
        
      
          
    • Speed: RTF below 1 is faster than real time. Identical runs spread by 20–30% on a busy host; repeats report the median.
      • 
          
    • Level: RMS and peak describe loudness and headroom; they are level checks, not quality scores.
      • 
          
    • Quality: the small number under each score is the change from the unprocessed input. DNSMOS needs no reference.
      • 
        
    
        
    A difference of a few hundredths in DNSMOS or STOI on a single recording is not a ranking.

    About Acoustic world
    
      
    
        
    Build a scene
    
        
    Start from a preset, then add talkers and noise sources under Settings › Sources — up to eight — and give each a role: target talker, other talker or noise. A source either stays still or follows its keyframes: a time, a position and the direction it faces. Drag the numbered points on the floor plan or type the values; double-click the floor to put the selected source there at the timeline's time — as a new keyframe, or by moving the one already at that time.
    
        
    Problems show up while you edit — a keyframe outside the room, too close to the microphone or inside an obstacle, or a path faster than walking pace — and Render stays off until they are fixed.
    
        
    What is rendered
    
        
    Every path from a source to the microphone — the direct sound and reflections up to second order — follows the motion continuously, with Doppler shift, a talker's measured directivity, wall absorption and sound bending around obstacles. The reverberant tail is matched to the room's materials. The renderer and its limits are described in docs/algorithms/audio/dynamic_scene.md.
    
        
    References and scores
    
        
      
          
    • Target talkers: every talker whose role is Target.
      • 
          
    • All speech: every talker, target or not; the default for noise-suppression models.
      • 
          
    • Near region: every talker inside the near radius, faded out across 0.2 m at its edge, silent while nobody is inside; the default for voice-isolation models.
      • 
        
    
        
    Settings › Scene › Reference sets what a reference keeps of each talker's sound: Early, the direct sound and 50 ms of reflections (the default, as in training); Direct, 6 ms; Full, with reverberation; Anechoic, the dry clip. Switching between the three references re-scores the same render; another reference type needs a new render. Without a model the output is the microphone itself, so the scores describe the input.
    
        
    Limit map
    
        
    Pick two parameters and their values; a parameter changes every source of its kind by the same amount, and each cell renders the scene once with the model. Open a cell to listen to it, and retry a failed or cancelled one.
    
        
    Files
    
        
    Scene JSON keeps the scene and references to its audio. The scene package also carries the audio, the renders and the report; importing it reproduces the render.
    
      
    
        
    
      
    About Pipeline
    
      
    
        
    The recipe supplies its augmentation knobs only. The audio is what you choose in Settings; the training corpora are never read.
    
        
      
          
    1. Build a row: pick a recipe and some audio, and optionally a model to score with.
      2. 
          
    2. Follow the stages: each shows what it drew and how the pair changed; a skipped stage says why.
      3. 
          
    3. Read the model: effective SNR is what is left to remove, and the model's score at each stage is how it copes.
      4. 
        
    
        
    Effective SNR counts as interference everything that is not the target: noise, other talkers, late reverberation past an early target, and transmission damage.
    
        
    ← → step through the stages; Ctrl+Enter builds.
    
      
    
        
    
      
    About Models
    
      
    
        
    Each card is one catalog entry. Default is the release preset for its task; candidate, reference, experimental and diagnostic say how far a model is from release.
    
        
      
          
    • Details lists the files, their hashes and the benchmark records that name the model.
      • 
          
    • Compare gate records puts the released gate records of several models side by side.
      • 
          
    • The integrity check verifies ONNX files, hashes, sidecars and graph contracts; it does not judge audio quality.
      • 
        
    
      
    
        
    
      
    About History
    
      
    
        
    Every playground run, speaker check, comparison and live session this server kept. Open a run to show it again on its own screen.
    
        
    Audio is kept for a bounded number of runs, so an old run may have lost its audio.
